# ICEcore 开发与调试规则

Last updated: 2026-10-10

本文直接记录本项目实现、资源、构建与调试所需的通用要求。与根目录 [工作区规则](../AGENTS.md) 配合使用；具体领域要求按 [文档索引](INDEX.md) 查阅。仅修改文档时读取“文档与规则维护”；其它任务读取对应章节。

## 文档与规则维护

- 本项目规则只由根目录 `AGENTS.md` 和 `docs/` 承载；必要规则写入本地正文并加入索引，不通过外部规则文件、规则快照或其它项目的记忆索引间接继承。
- 玩法、开发者工具、配置、数据保存、权限、运行目录、UI、语言、兼容和动画变化，更新 `content-implementation.md` 对应条目；较大领域按需拆分专题文档，记录行为、入口、资源、实现链路和验证边界。
- UI 文档记录 PNG、布局、遮罩、滚动、屏幕/HUD 和编辑器相关约束；动画文档记录投射物、临时手持物、姿势、受击与关键帧。默认属性、奖励池、覆盖和回退规则按实际功能维护，不添加没有需求的系统。
- 规则文件与实现文档不得混为发布说明。稳定使用说明放独立 Wiki，版本增量放根目录中文 `CHANGELOG.md`，编写前读取 `changelog-guidelines.md`；不依赖其它项目的格式或双语模板。
- 新增、删除或迁移规则时，检查本地正文、开工路由和索引链接是否同步；逐条确认适用性，避免复制其它 Minecraft 版本或其它模组专属要求。

## 事实来源与工具

- 先确认真实结构、代码、资源和注册 ID；上游行为以当前指定版本的源码、JAR、元数据、配方、战利品表和日志为依据，外部网页只用于定位。
- 结构性问题优先 CodeGraph；字符串、日志、注释、资源键和已锁定文件细节使用 `rg` 或局部读取。大文件先定位标题或关键词，中文使用显式 UTF-8。
- `rg`、`git`、`node` 等不在 PATH 时，确认原因后切换可用的绝对路径或 PowerShell、`Select-String`、`.NET`、Gradle wrapper；不反复重试相同失败命令。Windows脚本执行前核对解释器真实路径，排除WindowsApps应用别名；写入后回读目标字段，不能只看退出码。JAR 读取遵循根目录的本地规则与经验文档第 23 条。
- 输出前核对文本长度与工具 token 预算；文档和字节码每次先构造完整批次文本，以长度断言限制整批最多 6000 字符，超限必须拒绝输出并拆分；断言后不得追加未经计数的正文、搜索结果或工具描述；禁止仅以行数限制代替长度门禁。工具发现先只输出名称，仅对实际使用的工具读取描述。截断后缩小范围重读，不以截断输出宣称已完成阅读。
- 日志、启动参数和进程命令行输出前隐藏 access token、UUID、clientId、XUID、JWT 等敏感字段；默认排除完整启动参数行。

## 服务端权威、同步与性能

- 玩法状态、随机结果、奖励、权限、持久化、结算和最终位置由服务端决定；客户端只承担输入、显示、预览、缓存、动画和临时视觉状态，不能以客户端修补掩盖服务端错误。
- 网络只发送状态变化、必要快照或按需详情；空闲时不得每 tick 重发完整大对象。客户端缓存通过版本号、内容 key、指纹或明确脏标记失效。
- 多人流程检查本地输入锁、服务端 pending、快照顺序和重复提交；按钮变灰不能代替服务端校验。
- 高频路径必须约束触发频率、集合扫描、对象分配、主线程工作和生命周期；列表、图片、文本布局按需缓存，内容变更时失效。诊断日志默认关闭，开发者模式不自动开启逐帧采样。

## 数据、配置与兼容

- 可配置内容明确内置默认、用户覆盖、运行时缓存与保存格式的优先级；管理工具暴露实际可调项，不以空摘要或隐式兜底代替。
- 从已有内容中选择使用列表、网格或可搜索选择器；名称、说明、数值、概率和权重等自由字段才使用输入框。
- 修改内置默认时核对当前客户端外部数据是否遮蔽默认值；涉及同一内容且非用户明确只改单侧时同步维护。NPC、任务、教程等自定义内容仍按根目录规则写入客户端，不能复制进模组作为默认示例。
- 删除覆盖通常恢复内置默认，不直接删除内置定义，除非对应功能规范明确允许。
- 兼容实现前读本项目对应条目，并从实际目标版本 JAR 核对 mod ID、注册项、资源引用、获取来源和执行入口；如任务涉及分类，排除不存在、占位或无生存获取来源的内容，核对重复和规则冲突。

## UI、语言与资源

- 有原生展示时先核验完整调用链与整合包接管入口，禁止自行复刻内容/样式；底层背景API不能代替GuiGraphics Tooltip及Forge事件，Jade沿用标准存储提供器。相关纠正必须升级原错误记录与针对真实兼容JAR的门禁。

- 页面操作反馈先检查当前页面既有提示链路；CozyCafe电脑必须复用原生提示包与setErrorMessage区域，遵守AGENTS.md页面反馈例外。修改时运行CafeHoursCompatibilityTest，禁止改用原版overlay/title/chat。

- modal 绘制顺序为底层界面、统一半透明遮罩、当前弹层；底层 tooltip、hover、文字和动画不得穿透。遵循本项目实际界面风格，不借模糊或不透明遮罩掩盖层级问题。
- 内容溢出时才允许滚动并显示滚动条；滚轮、拖拽、裁剪与命中共用视口。文本、按钮、数字和预览保持稳定尺寸与响应式边界。
- 改贴图前测量尺寸、透明边界、九宫格边距或端帽；仅拉伸可重复区域。复制图标到本模组资源树并用本地命名空间引用，避免隐式外部资源依赖；有意复用外部资源时明确依赖与可选门禁。
- 新增、移动或删除语言键前读相关实现条目与实际语言文件；若存在专门语言分类文档，按索引读取。`zh_cn.json` 与 `en_us.json` 分类顺序一致，先查可复用键，语义或占位符不兼容时才新增。
- JSON 不加注释；含格式参数并显示字面百分号时写 `%%`。玩家可见文本使用翻译键，中文同类术语一致。
- 新注册 ID 使用稳定、可读的英文名称，不复用已有 ID；只有明确需要旧存档兼容时才保留旧别名。

## 动画与临时状态

- 服务端同步必要起点、命中点、时长、结算点和物品；客户端以 partial tick 插值。视觉位移不通过服务端每 tick 传送实现，服务端负责权威安全位置和最终校正。
- 弓、弩、三叉戟、药水和攻击姿态尽量复用原版状态与计时；结束、中止、断线和超时时恢复临时手持物、使用状态、姿态、输入和镜头。
- 关键帧采用“初始位置 + 当前帧偏移”，不得逐帧累加造成漂移。修改后推演输入、pending、结算、同步、消费、tick、逐帧插值和恢复全链路。

## 构建、部署与调试

- 使用项目 `gradlew.bat` 和 Java 17 工具链；当前 `build.gradle` 明确 `JavaLanguageVersion.of(17)`。基线 Forge 47.4.10，其它 47.x 验证须核对实际解析坐标并恢复基线。
- 交付仅使用完整 `build` 完成且 `verifyProductionJar` 通过的 `build/libs` 成品；不能交付重混淆完成前的JAR或IDE开发包。检查已有客户端包时可执行 `verifyProductionJar -PproductionJar=<绝对路径>`，并比较SHA-256；该任务只读目标包，拒绝仍含映射表中Minecraft开发方法名的生产包。
- PowerShell 调用 Gradle 时，将 `-D` JVM 系统属性作为完整单引号参数传递，例如 `'-Dnet.minecraftforge.gradle.check.certs=false'`；避免点号参数被拆分为任务名。先核对日志中的任务图，再判断编译结果。
- 窄验证优先，按风险扩大到完整构建；`clean` 单独执行成功后，再以新的 Gradle 进程执行 `test` 或 `build`，禁止合并在同一命令。纯文档修改使用 UTF-8、内容、引用与 Git 边界检查。
- IDEA 与命令行使用同一个 Gradle user home；同步反复下载时核对用户 `GRADLE_USER_HOME` 与 IDEA 设置中的 Gradle user home（`gradle.settings.xml` 的 `serviceDirectoryPath`）。不一致时通过 IDEA 设置修改，不直接编辑运行中的配置 XML；版本更新或首次依赖下载属于正常现象，不把历史缓存位置硬编码成项目要求。
- 部署新 JAR 前确认目标 Minecraft 客户端/服务端进程已退出，禁止热替换已发现或加载的模组 JAR，避免半旧内容导致假性类缺失。
- 只有用户明确授权后才启动客户端；授权调试时按构建、退出旧进程、复制 JAR、启动、核对日志/崩溃报告时间戳、定位根因、最小修复的顺序验证。构建成功不能代替实机验收。
- 服务端发行包排除 world、logs、libraries、本地缓存以及用户/封禁/白名单等运行时数据，只保留必要配置、mods、脚本、图标和启动文件；用户明确要求备份运行数据时另行处理。
