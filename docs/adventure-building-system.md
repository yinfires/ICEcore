# 冒险模式建造系统

本页面向维护服务器规则的开发者。系统配置保存在每个世界的 `data/icecore_building.json`；管理员命令需要权限等级 2，修改后立即校验、保存并同步到在线客户端。

## 1. 配置模型

### 一体式冰箱

`icecore:fridge` 使用同一结构解析覆盖上下两格。加入有效方块列表后，两格都必须满足区域限制和放置空间检查；点击任意半边均以整台进行扳手拆除。上下库存以及制冰/保鲜升级共同参与非空检查和确认指纹；两次 Shift 右键强拆会清空整台内容与升级，只返还一个冰箱。确认期间任意半边内容变化均要求重新确认。

### 区域（`regions`）

区域定义的对象键必须与 `name` 相同：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `name` | 字符串 | 区域唯一名称。 |
| `dimension` | 字符串 | 维度注册名，例如 `minecraft:overworld`。 |
| `pos1`、`pos2` | 三个整数的数组 | 两个角点，坐标为闭区间；数组顺序不影响最小/最大值计算。 |

缺少 `dimension`、任一坐标或坐标数组长度不是 3 时，区域没有有效范围。

### 方块列表（`blockLists`）

方块列表对象键必须与 `name` 相同：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `name` | 字符串 | 列表唯一名称。 |
| `entries` | 字符串数组 | 方块注册名或 `#命名空间:标签`；命中任一条目即属于列表。 |
| `regions` | 字符串数组 | 可放置/拆除的区域名称。多个区域为 OR。空数组表示不添加区域条件。 |
| `supports` | 字符串数组 | 承托方块列表名称。多个列表为 OR；放置时点击的方块必须命中其中一个列表。空数组表示不添加承托条件。 |
| `allowedFaces` | 字符串数组 | 附加的点击面限制，可写 `up`、`down`、`north`、`south`、`east`、`west`。`side` 只作为命令快捷方式展开为四个水平面，不应写入 JSON。空数组表示所有面。 |

列表只有区域或承托两类基础条件至少存在一类时才有效；只有 `allowedFaces` 的列表无效。一个方块命中多个有效列表时，所有列表都必须通过。放置判定为“区域条件 AND 承托条件 AND 方向条件”；拆除判定方块是否属于有效列表，并检查匹配列表中的区域条件，不判定承托和方向。仅有承托限制的有效列表同样可以拆除，但没有额外区域范围限制。

## 2. JSON 示例

下面的完整示例允许木板在 `town` 区域内、对着承托列表 `solid_support` 的上面或侧面放置：

```json
{
  "formatVersion": 1,
  "regions": {
    "town": {
      "name": "town",
      "dimension": "minecraft:overworld",
      "pos1": [0, 64, 0],
      "pos2": [32, 80, 32]
    }
  },
  "blockLists": {
    "solid_support": {
      "name": "solid_support",
      "entries": ["minecraft:stone", "#minecraft:logs"],
      "regions": ["town"],
      "supports": [],
      "allowedFaces": []
    },
    "wood": {
      "name": "wood",
      "entries": ["minecraft:oak_planks"],
      "regions": ["town"],
      "supports": ["solid_support"],
      "allowedFaces": ["up", "north", "south", "east", "west"]
    }
  }
}
```

`formatVersion` 必须为 `1`。区域绑定必须引用已有区域，承托绑定必须引用已有方块列表；未知引用、对象键与 `name` 不一致或方向值非法都会使本次加载/修改失败，并保留上一份有效配置。

## 3. 命令参考

命令根为 `/icecore build`，全部要求权限等级 2。名称参数会根据当前存档补全；`block ... add <entry>` 还会补全已注册方块和已加载的方块标签。

| 命令 | 用途 |
| --- | --- |
| `/icecore build reload` | 重新读取世界 `data/icecore_building.json`；成功后立即重建规则并同步客户端。 |
| `/icecore build region add <区域名>` | 创建没有坐标的空区域。 |
| `/icecore build region add <区域名> <坐标1> <坐标2>` | 创建区域并设置维度与闭区间范围；维度取执行命令所在世界。 |
| `/icecore build region set <区域名>` | 进入该区域的调整模式；执行者必须在主手或副手持有普通木棍。 |
| `/icecore build region set <区域名> <坐标1> <坐标2>` | 直接覆盖区域维度与范围。 |
| `/icecore build list add <列表名>` | 创建空方块列表。 |
| `/icecore build list remove <列表名>` | 删除方块列表，并移除其他列表对它的承托引用。 |
| `/icecore build list block <列表名> add <注册名或#标签>` | 向列表加入方块注册名或方块标签；注册名中的 `:` 和标签开头的 `#` 会作为一个完整条目解析。 |
| `/icecore build list block <列表名> remove <注册名或#标签>` | 从列表移除一个条目。 |
| `/icecore build list region <列表名> <区域名> add` | 将列表绑定到区域。 |
| `/icecore build list region <列表名> <区域名> remove` | 删除列表与区域的绑定。 |
| `/icecore build list support <列表名> <承托列表名> add` | 要求列表中的方块只能贴着承托列表中的方块放置。 |
| `/icecore build list support <列表名> <承托列表名> remove` | 删除承托列表绑定。 |
| `/icecore build list face <列表名> <方向> add` | 添加一个方向限制；允许重复添加而不会产生重复项。 |
| `/icecore build list face <列表名> <方向> remove` | 删除一个方向限制；`side remove` 会同时删除四个水平面。 |

方向参数为 `up`（上面）、`down`（下面）、`north`、`south`、`east`、`west`（四个侧面）或命令快捷方式 `side`。可以多次执行 `face ... add` 组合多个方向。

## 4. 调整模式

执行不带坐标的 `region set` 后，木棍临时显示区域名并带附魔光效。手持该木棍左键方块写入 `pos1`，右键方块写入 `pos2`；输入会被拦截，不会破坏或使用方块。主手/副手均支持，切换物品、不再持有木棍、退出服务器或切换维度时退出并恢复原木棍。客户端在两个坐标均存在且处于对应维度时绘制区域的三维线框边界；开发者调整不受玩家游戏模式限制。

## 5. 客户端预览

预览只在冒险模式且交互距离足够时显示。手持具有有效区域或承托基础限制的可放置方块时，客户端先根据方块状态的结构属性归一化关键位置，再在预计的关键位置及其全部去重后的占用位置渲染对应方块的半透明模型；模型会保留原方块纹理和形状，不额外绘制边框。当前放置判定失败（区域、承托、方向、方块状态或任一占用位置不满足）时，整个模型的顶点颜色改为深红色，并使用与成功预览相同的单层原版半透明渲染批次，仅改变顶点颜色；成功与失败预览各自在独立批次中只提交一次，避免同一位置模型重复渲染。没有有效放置限制的方块、非方块物品和调整木棍不显示放置预览。放置成功后，在服务端背包同步完成前的短暂窗口内会隐藏旧目标预览，避免下一手持物品沿用上一目标。

手持扳手时，只有准星指向属于有效方块列表的受管方块才显示该方块（含多格结构）的深红半透明模型；列表配置区域时，目标还必须位于该区域内。可见扳手模型直接复用无法放置预览的方块模型、染色、透明度、无边框表现和 `RenderType.translucent()` 批次；原方块由区块重建读取阶段的隐藏坐标状态从新网格移除，不使用只写深度的前置遮罩，避免半透明模型只能与天空色混合。进入、切换或离开拆除目标时，区块网格与预览按受影响 section 分两阶段提交：新目标所在 section 完成隐藏后才显示对应预览格，旧目标所在 section 恢复后才移除对应旧预览格，因此异步区块重建期间每个结构格始终恰好由原网格或预览覆盖，不出现缺口、双模型或颜色闪变；快速扫过多个目标时按最新目标排队合并，不同步编译区块。区域外、未受管或没有有效列表绑定的方块不显示扳手预览；仅有承托限制的有效列表仍可显示预览并拆除。扳手对着已进入拆除目标的受管方块右键时，会先阻止目标方块本身的交互；即使服务端因距离、区域、背包空间或其它最终条件拒绝拆除，也不会因此触发门开关等方块行为。无论扳手在主手还是副手，只要准星指向受管目标，右键都不会触发目标方块交互；持扳手的那只手负责发起拆除，另一只空手或副手的重复交互被一并拦截。空容器一次右键拆除；非空容器或厨具会阻止普通拆除。第一次 Shift+右键记录玩家、维度、主方块、方块状态和内容指纹，60 tick 内对内容未变化的同一目标再次 Shift+右键才会强拆；强拆只返还方块并清空内部内容，不生成内容掉落。超时、换目标、内容变化、换维度、退出或成功拆除都会使确认失效。

## 6. 运行时判定

冒险模式扳手拆除增加承托依赖保护：按当前 `supports` 和 `allowedFaces` 判断整个目标结构各格六邻格的依赖，排除结构内部格。任一相邻方块的有效列表匹配目标承托及向外方向即可阻止拆除，不检查依赖方块的区域，也不因存在其它承托而放行。普通右键与 Shift 强拆均显示“该方块被其他方块依赖”；先拆依赖方块后才可继续。检查先于容器确认和背包容量，并清除旧强拆确认，不释放已认领的右键。

放置与拆除使用服务端最终判定，并遵循原版交互距离。多格方块由 Forge 原生放置流程处理；客户端预览仅为视觉提示，距离不足时不显示，服务端会重新校验实际放置结果。扳手拆除会将命中的结构状态归一化到关键位置并整体处理。空目标先验证背包能容纳返还方块；非空目标须完成上述二次 Shift+右键确认，且只返还方块本身，失败时不改变世界。
扳手拆除还必须满足：目标方块属于至少一个有效方块列表；匹配到区域限制的列表时，目标关键位置必须位于这些列表允许的区域内。承托和方向限制不影响拆除；仅有承托限制的有效列表可在交互距离内拆除。拆除请求仍只在冒险模式下处理。

建造系统需要返回给玩家的即时反馈统一通过 `feedback.PlayerFeedback` 发送到底部信息栏，不使用聊天栏；Forge 47.4.10 的原版 overlay 保持 40 tick（2 秒）后在 20 tick（1 秒）内淡出。控制台等非玩家命令源仍使用命令输出。

## 右键交互优先级（2026-10-15）

有效建造放置独占右键；区域、承托、方向、距离、多格占用或碰撞不满足时允许普通交互。放置事务被 Forge 拒绝后仍不回退交互。扳手仅在目标有效列表与区域允许拆除时独占右键；背包满和内容确认属于拆除执行阶段，不放行交互。非有效目标或区域外可正常交互。

## 冒险模式普通交互限制

全局配置 `config/icecore/adventure_interaction.json` 包含 `formatVersion: 1`、`blacklist` 和 `whitelist` 数组。字符串 `namespace:block` 匹配精确方块，`#namespace:tag` 匹配方块标签，`{"mod":"namespace"}` 匹配来源命名空间，`{"mod":"namespace","tag":"namespace:tag"}` 匹配二者交集。首次创建空数组，不内置整合包内容。有效建造放置、扳手拆除与调整优先；坐标特例和白名单豁免本系统黑名单；其它限制仍有效。只禁止冒险模式普通右键，OP不豁免；左键和其它模式不变。

特例文件为存档 `data/icecore_interaction_exceptions.json`：`{"formatVersion":1,"exceptions":[{"dimension":"minecraft:overworld","pos":[1,64,2],"block":"minecraft:oak_door"}]}`。按状态属性复用 BuildingStructure 的主位置，门/床上下或前后半对应同一特例，不读取未加载邻格。状态变化不失效；换ID不匹配，放回原ID重新匹配。特例按存档独立，记录直到主动删除。

入口为 `interaction.InteractionConfig`、`InteractionExceptions`、`InteractionManager`、`InteractionSnapshot`、`InteractionCommands`、`InteractionEvents`、`ClientBoundInteractionPacket` 和 `InteractionClientState`。建造事件中有效操作先认领，普通禁止事件返回FAIL并在LOWEST重申；客户端在现有MultiPlayerGameMode内部预测入口及BlockState.use阻止普通使用，外层原版请求包保留。网络协议11，包23发送展开后的方块ID与特例；登录、成功修改及标签更新同步，断线清空。服务端权威重检，不依赖客户端标签加载顺序。

启动、命令编辑及标签重载编译缓存，复杂度O(R×B)，R为规则数、B为注册方块数；右键为集合查询和可选坐标键查询O(1)，结构解析缓存有界为注册方块种类。无tick扫描、交互I/O、反射或重复日志。未知合法选择器保留为未命中，重建时汇总最多20项。特例编码最多1000000字符，超限拒绝保存。规则与特例重载先全部解析，失败保留上一快照；写入使用同目录临时文件加原子替换，不支持原子移动的文件系统回退普通替换。

命令、人工标签查看和当前整合包分类见Wiki《冒险模式交互限制》。验证入口：InteractionConfigTest、InteractionIntegrationTest、BuildingInteractionContractTest；保存失败测试检查旧目标及临时文件清理，真实MC交互仍需授权实机验证。

移除命令补全只展示所选黑/白名单的对应类型条目；modtag标签按已选择来源过滤。未加载但已保存的条目仍可补全删除。添加命令继续使用当前注册表候选。
