# 咖啡馆顾客、声望与每日客流

更新日期：2026-10-23。

用途：记录已接入的顾客与经营机制、代码链路及验收边界。替代原未实现客流方案；实现及构建验证不等同于实机验收。

## 顾客与共享账户

正式内容位于指定实例 config/icecore/cafe_customers.json，服务端读取并同步。模组不内置 A/B/C 示例定义，也不读取在线玩家皮肤。

实例配置的 customer_a / customer_b / customer_c 分别使用顾客A/B/C翻译键、200声望上限和基础权重1。喜好、厌恶引用正式 icecore:recipe_manager/ 标签：A为实惠、米面/珍稀，B为甜、清淡/浓郁，C为辣、肉食/素食。三类首版均为宽臂史蒂夫。

各类型保存独立账户，总声望仅汇总当前有效类型；旧原生声望不导入。类型删除保留账户，恢复ID恢复进度，降低上限截断。每120总声望显示一星、最高五星；星级仅显示，基础识别范围固定为零星范围，已配置范围覆盖继续生效。电脑页面不额外绘制总声望文字；电脑物品提示沿用已有共享总声望入口。

本地PNG置于同级 cafe_skins/，配置相对文件名；64×64皮肤可指定slim。资源包皮肤使用resource资源路径。路径穿越、符号链接逃逸、单文件超64KiB和过大总同步包被拒绝。缺失或不受支持的皮肤使用宽臂史蒂夫。生成后实体与菜单保存类型、变种及本次口味规则快照；实体CustomName由名称翻译键设置，Jade沿用原生实体名称，无重复名称提供器。真实Jade 11.13.3的ObjectNameProvider.getEntityName调用Entity.m_7755_（getName），两版CustomerEntity均未覆盖该方法，契约测试覆盖此链路。

## 点餐、清桌和结算

每次到访在可成立的组合中等概率选择：主食；主食加饮料或点心；三类齐全。第二种组合两种附加课可用时等概率。执行顺序保留原生饮料→主食→点心。

每类按结果物品去重。存在不带厌恶标签的菜时排除厌恶菜；有喜好菜时90%选择喜好池、10%选择全部合格池。喜好池权重为1+0.5×(喜好命中数−1)。全部厌恶时才允许厌恶回退。订单生成后固定本菜喜恶计数；后续课程重新读取当前有效菜单，缺失课程跳过。

每道订单保存耐心期限，tick超时检查和服务入口使用该道快照。需求实际出现才开始原生等待计时，使用服务端运行tick。速度在耐心的1/3、2/3处划分，边界归前一档；快+2、中+1、慢0。每菜声望为速度奖励+喜好命中数−厌恶命中数；三类基础奖励均为0。服务超时扣对应类型2声望并结束到访，非服务取消不扣。已结算菜品不回滚。

原生速度价格倍率通过付款入口暂时屏蔽速度条件移除，其它品质、属性和价格计算继续走真实CozyCafe方法。快和命中喜好各独立20%概率获得小费，每次max(1,floor(实际整数菜款×10%))，可叠加。

付款与超时共用持久化订单标识去重；共享货币入账失败时款项累计到BigInteger待入账账户，余额有空间后每秒尝试一次，不溢出、不丢币、不掉币。去重日志保留最近8192单，菜单自身另存Settled状态。正常Minecraft保存生命周期内重载不会重复结算；不声称跨多个存档文件的异常断电写入具有数据库事务保证。

吃完的器皿或脏盘未取走时，不开始下一道点单及其等待；最后一道吃完可以正常离场，器皿仍留桌并阻止新客。清桌复用正常背包转移，满包留桌。实际食物、待返还器皿或脏盘均阻止新客和强拆；已有器皿链路不另建库存。

## 营业和人数快照

全服每天只允许一场，主世界06:00–18:00接客，主动停业当天不可重开。仅开店电脑的菜单、座位、总声望、菜单吸引和时间基准参与本场。停接不清客、不断后续课程、不统一限时收尾。

当日额度=四舍五入((8+0.04×开店总声望)×菜单倍率)。菜单按不同有效结果物品计数，不受份数或品质影响。菜单数量1/5/10/25/50/100对应倍率0.75/0.90/1/1.25/1.5/1.75，中间线性插值，两端封顶；默认三类声望范围内为6–56人。只在最终人数取整，不乘营业时长、座位数或接待速度。

类型抽选权重=基础权重×菜单喜好倍率×(1+0.20×当前类型声望/上限)。开店菜单存在安全且可选择的喜好菜时倍率1.25，否则1。每位顾客独立抽类型及皮肤；本场声望变化只改变客群权重，不重算额度。

同行1/2/3/4人概率：额度≤6时85/12/2/1%，额度24时65/23/9/3%，额度≥56时45/30/17/8%，控制点间线性插值；按剩余额度和实际空座缩小批次。

## 倒计时和接纳状态

开店时间基准=max(预计距离18:00的运行tick，完整12小时窗口运行tick×3/4)，使用开店时dayDurationMultiplier。基础间隔=时间基准×平均同行人数/额度。每轮乘(1−0.20×当前空座比例)，再乘均匀0.8..1.2，最终限制200–900运行tick。首批同样计时；已开始的倒计时不因座位变化重置。

满座继续倒计时，到期只保存一个待生成机会。菜单可用状态变化、清桌和路线预热就绪唤醒机会，无法接纳时有界重试；路线恢复仅使用本场保存的座位名单，失败退避最高60秒，不在重试中扫描空间范围，不累积多批欠账。按服务端主线程先预留座位，再调用原生spawnCustomerAndTarget空用户名同步路径，实体实际入世后才提交接纳人数。失败释放本人的预留，不扣人数；部分成功仅消耗成功部分。生成后失败或服务超时不返还已接纳人数。

继续复用分tick每tick最多一次A*、单一接待点和有限导航恢复。开店结构快照包含暂被旧场占用的有效座位，但派客须再次检查真实空闲状态。既有顾客、器皿和跨日旧场保留其UUID/座位；各电脑保留未完成座位记录，阻止清空数据破坏旧客流程。

主世界SavedData icecore_cafe_customers保存迁移schema、账户、场次UUID、最后开店日、额度、接纳人数、菜单/声望快照、倒计时、时间基准、座位、菜单吸引、旧场座位及结算状态。前进跨18:00或多日立即结束接客；时间倒退不撤销已消费的开店资格。重启不补满额度。

## H查询与网络

可重绑定H在正常游戏输入时打开，ESC或H关闭，不暂停。按配置顺序只列顾客名称、喜好、末尾厌恶与当前声望/上限，不显示模型或经营摘要。名称及标签按宽度换行，右侧预留声望区域；厌恶红字，黑色删除线独立绘制。

背景调用现有WoodPanel；滚动条通过CozyCafeNativeScrollerMixin适配真实MenuSelectorScreen的renderScroller、mouseClicked、mouseDragged和mouseScrolled，不复制贴图或重写滚动算法。逻辑像素偏移仅在绘制时映射到原生33个拇指位置，规避原生长列表整数步长为零；裁剪、命中和输入使用同一视口转换，释放鼠标直接结束原生拖动，禁止进入空容器槽位交互。

登录与配置重载发送完整有版本快照，声望变化仅发送账户数据，不重复传皮肤。旧版本快照被拒绝，连接已断开不接收排队快照，退出清理客户端状态和纹理。布局仅在配置、语言或窗口变化重建；绘制只处理可见行。本地PNG按每客户端tick最多2个解码，渲染只查缓存；重载、退出释放纹理。

## 入口、性能与验证

2026-10-23启动报告修正：菜单提示使用既有CozyCafeNormalFoodTooltipMixin唯一接管，删除与其重叠的新Mixin。背景菜单行及背包槽均在原生getTooltipFromItem处记录本次ItemStack，最终只调用一次正常物品提示绘制，finally清除引用；无注册表搜索或额外同步。CafeCustomerUpstreamTest扫描所有已注册CozyCafe Redirect，拒绝同目标类/方法/调用点重复占用。

电脑菜单与选菜界面的悬停提示分别由CozyCafeManagerScreenErrorMixin、CozyCafeNormalFoodTooltipMixin接回GuiGraphics.renderTooltip(Font, ItemStack, int, int)，使用物品正常名称与描述，不显示CozyCafe页面追加的价格、分类和碗瓶说明。保留Forge物品上下文、GatherComponents与Pre事件，Modern UI沿原生sCenterTitle/titleGap绘制居中名称，不手绘或重命名标题。指定实例ModernUI/client.toml的centerTitle=true已只读核对；原生列表重载缺少物品上下文的问题由正常ItemStack入口修正。

CafeCustomerKeys.Events.nameplate在Forge RenderNameTagEvent中仅对CustomerEntity设置DENY，禁止已有和新增顾客的头顶名称；不修改CustomName或Jade提供器。每次名牌事件仅常数类型判断，不扫描实体、不分配文本、不发同步包。

服务入口为compat.cozycafe.customer.CafeCustomers、CafeCustomerData、CafeCustomerConfig、CafeCustomerEvents。数学及抽样位于CafeCustomerRules；网络为CafeCustomerSnapshot；UI、按键、皮肤位于其client子包。菜单缓存为最多32台电脑、单台最多缓存4096有效菜，菜单修改、NBT加载、数据包同步和配置重载失效，服务器停止清理。

营业tick只更新常数状态；到期才检查本场座位名单，满座不每tick扫座位。菜单tick只比较本菜单已有状态，变化时唤醒。无世界范围/注册表轮询、无渲染磁盘读写、无在线皮肤查询、无无界日志。磁盘读取只在配置加载/重载；保存交给SavedData生命周期。
