# 咖啡馆客流量计算方案

更新日期：2026-10-08。

用途：保存用户确认的客流计算边界、计算含义和后续实现验收要求。状态：设计方案，尚未实现；不代表 CozyCafe 或 ICEcore 当前行为。数值曲线与同行概率仍需平衡验证，不将讨论中的示例当作固定配置。

## 核心边界

- 只有开店时的总声望与有效菜单数量决定当日客流量。客流量是具体整数，表示当天最多可接纳的顾客人数。
- 有效座位、最长营业时间、平均完整接待周期只影响生成节奏与完成风险，不修改当日人数额度。
- 全部计算输入在开店瞬间形成快照。营业中的声望、菜单、座位结构、时间倍率、服务统计或配置变化不重新计算本场额度、计划间隔或同行分布。
- 实时空座、座位预留、路径安全和营业关闭条件仍须检查；快照不允许向无效座位生成顾客。
- 顾客可同批到访，单批为 1–4 人。客流压力较高时适当提高多人概率；生成总人数不得超过剩余额度。
- 有接客资格且持续有空座时，生成计时不得超过可配置的生成间隔上限。参考值单独列于文末。
- 当日额度是上限，不保证在短营业、满座或服务缓慢时全部用完。不把错过的机会积累为关店前补发任务。

## 当日客流量

| 输入或配置 | 具体含义 |
| --- | --- |
| 开店总声望 | 各顾客类型声望按既定规则汇总后的餐厅总声望 |
| 开店有效菜品数 | 开店时菜单中不同有效成品的数量；重复上架、份数或同一成品品质变体不重复计数 |
| 声望基础人数曲线 | 总声望到基础接待人数的非递减映射，使用可配置控制点 |
| 菜单人数倍率曲线 | 有效菜品数到人数倍率的非递减映射，提供小幅、递减且封顶的加成 |
| 人数取整规则 | 浮点人数到非负整数额度的统一规则；建议四舍五入，实际实现时固定并测试边界 |

公式：

`当日客流量 = 人数取整（声望基础人数曲线（开店总声望）× 菜单人数倍率曲线（开店有效菜品数））`

公式不得再乘营业时长、座位数或服务速度，也不得与座位接待能力取最小值。相同声望与菜单输入必须得到相同人数额度。

星级负责解锁总声望上限：到达当前上限后，通过升星任务开放更高上限；星级不在该客流公式中再叠加人数倍率。若人数曲线使用声望成长比例，分母必须是固定成长目标，不能是当前星级的声望上限，避免升星后客流反而下降。

单顾客声望与口味可用于客群构成、点单与声望收益；不独立改变全店人数额度。此文不确定它们的抽选权重和收益数值。

## 开店快照与营业时间

开店时保存总声望、有效菜品数、当日额度、有效座位名单、平均完整接待周期估计、时间系统参数、生成参数及同行分布配置。

`本次最长可接客时长 = min（单次营业时长上限，开店时距离晚间停止接客的预计实际时长）`

`完整营业基准时长 = min（单次营业时长上限，当天最早允许开店至晚间停止接客的预计实际时长）`

`节奏计算时长 = max（本次最长可接客时长，完整营业基准时长 × 晚开加密截止比例）`

`生成安排时长 = max（零时长，节奏计算时长 − 收尾预留时长）`

晚开加密截止比例固定表达用户要求的四分之三营业时间边界，使用语义参数引用，当前取值为 3/4。从最早开店到剩余时间降至该边界，允许生成节奏逐渐变密；剩余时间低于该边界后，节奏计算时长保持在边界值，不再因更晚开店继续缩短。该基准与本次实际截止时间分别保存，节奏计算时长不能延长真实营业窗口。

接待压力与同行分布也必须使用同一节奏计算时长，避免间隔停止缩短后，多人概率仍随晚开提高，形成绕过加密上限的间接加速。固定声望、菜单、座位、周期与其它配置时，在四分之三边界及之后开店，计划同行分布和间隔分布应完全一致。

时间统一换算为服务端实际运行 tick 或秒；日历时刻只用于营业窗口及自动关店判断，不与实际计时单位混用。开店后时间倍率变化不重算计划；实际进入晚间或达到营业时长上限时仍停止接新客，因此实际可经营时长可能短于快照估计。

每天可在窗口内自行选择开店；主动关店后当天不能重开，晚上自动停止接客。停接后保留已接纳订单的有界收尾流程，不直接把所有顾客清除或自动记为玩家超时。跨日、跳时、断线及重载不得重置额度或复制营业场次；具体状态机需在实现时结合现有系统核验。

营业中新增座位不加入本场快照；原座位被拆除、占用或失效后立即停止使用。修复后的原座位需重新满足真实接待条件才能恢复使用。

没有有效座位或可接客时长为零时，不执行除法、不启动生成；应沿用实际开店资格或明确提示无法接客，不把当日额度改算为零。

## 平均完整接待周期

含义：从生成并预留座位，到该座位再次能够接客的完整时间，包括行走、点单、等菜、吃菜及仍占用接待资格的离开阶段。

无历史数据时使用可配置周期基准；有历史数据时使用此前营业记录的平滑估计。营业中可以收集成功与取消订单的实际占用时长，但只用于下一次开店，不更新当前快照。基准、样本数量、平滑权重与异常样本界限都使用语义配置。

## 接待压力与同行分布

`接待压力 = 当日客流量 × 平均完整接待周期 ÷（开店有效座位数 × 节奏计算时长）`

接待压力只影响节奏：压力低时偏向单人，压力高时适当增加多人同批到访；在配置的压力过渡区间内平滑插值低压力与高压力同行分布。

压力超过可承载范围时提示额度可能用不完，不降低额度。多人到访只能改变忙闲分布，不能解决座位周转不足。

完成风险另按真实本次最长可接客时长评估；在晚开加密截止边界之后，风险继续上升，但不能用它再次提高同行概率或缩短间隔。

开店时根据有效座位数将同行分布限制为能够容纳的批次，并归一化概率。推荐把超过座位数的批次概率合并到最大可容纳批次。概率必须非负且总和为一。

`计划平均每批人数 = 各可用批次人数 × 对应概率的总和`

同批顾客分别占座、点单，不要求相邻座位或整组绑定；真正的同行组候位规则不属于本方案。

## 生成间隔

`计划平均间隔 = 生成安排时长 × 计划平均每批人数 ÷ 当日客流量`

`目标平均间隔 = 限制范围（计划平均间隔，生成间隔下限，生成间隔上限）`

`实际生成间隔 = 限制范围（目标平均间隔 × 随机波动系数，生成间隔下限，生成间隔上限）`

同批概率和间隔一起换算，不能先按单人计算生成次数，再额外乘多人数量。第一批同样使用受上限约束的计时。人数额度为零时不生成；安排时长不足时使用安全分支，不产生零间隔循环，也不保证兑现额度。

间隔上限优先于全天均匀分布：低额度、长营业时间时可能提前用完额度，之后停止生成。高额度、短营业时间可能受间隔下限、座位和服务周期限制而用不完。随机波动、边界裁剪与满座暂停意味着公式是计划节奏，不是精准完成承诺。

四分之三边界控制的是晚开带来的计划加密：受间隔上下界或同行分布封顶影响，某些输入可能已提前达到密度上限，不能保证每次晚开都出现可见加密。但绝不突破计时边界来强制加密；边界之后不再补偿晚开，实际经营时间缩短会减少用完额度的机会。

## 实时接纳与计数

`本次接纳人数 = min（抽取的计划批次人数，当前有效且未占用未预留的快照座位数，剩余额度）`

实时空位必须扣除已分配给在途顾客的预留。按服务器主线程顺序先预留、后生成；部分失败只撤销失败部分，不得释放已成功顾客的座位。

- 成功预留座位、生成并启动接待后，每位顾客消耗一个额度。
- 生成、路线预留或导航启动失败不消耗额度，并释放相关临时状态。
- 已接纳后超时、取消或离场不返还额度，避免无限补客。
- 无空位时暂停生成计时，不积累多批欠账；恢复后继续原进度，不立即补发。
- 当前空位不足导致批次缩小时，不重新计算计划平均人数或间隔；剩余额度在后续正常批次使用，不保证补齐。
- 额度用完、主动关店、自动关闭或结束接客窗口后停止生成。

最大间隔约束的是有资格接客期间的累计计时，不保证满座、路径不可用或停业期间每隔上限时间一定生成。失败重试须有有界退避，不能每 tick 无限制创建实体或导航。

## 展示、性能与验证要求

建议展示当日最高接待人数、已接纳人数、剩余额度、计划到访节奏及无法用完额度的风险。成功完成订单数单独统计，不将接纳数误称为已完成订单数。

服务器决定快照、随机结果、额度、预留与生命周期。开店时按菜单和有效座位规模计算一次；营业 tick 只更新计时和缓存计数，空位通过座位状态事件维护，生成时才核验目标座位。不在 tick 内重扫全部菜单、家具、区域或全世界实体，不同步 I/O、不无界日志。快照和计数变化才同步客户端。

后续实现至少验证：

- 固定声望和菜单后，改变座位、营业时长和周期不会改变额度；提高声望或菜单数量不使额度下降。
- 营业中改变任一计算输入不重算本场；下一次开店使用新值。
- 零额度、零座位、零时长、收尾时间不足和不合法配置不触发除零或高频循环。
- 任意同行分布和波动下，计时不超过上限；概率合法，单批人数不超过四人、空位及剩余额度。
- 多顾客同批、部分生成失败、满座恢复、拆椅、取消、关店与重载不会重复计数、重复预留或超过额度。
- 长营业低额度允许提前耗尽；短营业高额度允许用不完；晚开、提前关和满座不触发集中补客。
- 固定其它快照输入，分别在剩余完整营业时间、四分之三时间、二分之一时间及更晚开店：四分之三之前允许计划人数速率提高；边界及之后的同行与间隔分布一致，实际关闭时间仍随晚开缩短。完成风险不得参与二次加速。
- 本场服务记录只影响下一场周期估计；时间倍率变化不重算本场，自动关闭仍有效。

## 参考值与待校准项

生成间隔上限参考值为 **45 秒**，应允许配置修改；它不作为公式内的固定常量。单批人数 **1–4 人**为当前需求边界。

晚开加密截止比例当前为 **3/4**，这是用户指定的规则边界，而非任意平衡示例；公式统一引用其含义。

声望人数控制点、菜单倍率上限、生成间隔下限、周期基准、收尾预留、压力过渡区间、同行概率与随机波动幅度尚未定值。所有公式使用参数含义，参考值单独维护；实现后以实际完整接待周期、多批次随机分布和不同营业时长进行校准。
