## 工具

运行环境为Node.js，JAR资源首次读取依赖PowerShell 7的pwsh.exe，可用PWSH_PATH指定路径。

| 命令 | 作用 |
| --- | --- |
| `node tool/recipe-sync/sync.mjs check` | 校验并列出将变化的文件、来源SHA-256及跳过项，不写客户端 |
| `node tool/recipe-sync/sync.mjs diff` | 提供完整before/after内容及文件差异清单 |
| `node tool/recipe-sync/sync.mjs apply` | 保存备份后写入客户端和manifest |
| `node tool/recipe-sync/sync.mjs rollback` | 恢复最近一次apply；拒绝覆盖应用后的人工编辑 |

可追加 `--source <正式JSON路径>`、`--client <客户端路径>`。默认路径来自根目录工作区规则。

状态保存在客户端 `config/icecore/recipe-sync/`。manifest记录来源指纹、文件内容及逐配方结果；rollback.json保存最近一次有文件变更的应用前内容和manifest；无差异apply不覆盖有效备份。语言和描述按自有键合并，其它生成文件拒绝覆盖人工内容。配方编辑被拒绝时保留最近成功配方及容器文件；首次错误不移除旧制作途径。相同产物存在首次失败配方时保护该产物旧途径。

## 设备转换

以下是当前转换器及真实上游入口核对结果，操作和重载仍须逐类验收。

| 设备 | 数量、时长与原生流程 |
| --- | --- |
| 砧板 | 单件输入；缺省菜刀，保留擀面杖；全部输出按管理器数量且chance=1 |
| 竹匾 | 原生drying类型，1800 tick，1→1；不替代环境条件 |
| 蒸笼 | 原生steamer类型，600 tick，1→1；沿用关盖和热源 |
| 烤炉 | 无序单件展开，九格限制；400 tick，batch上限9且受容量约束；原生稳定等待及热源入口 |
| 混合碗 | 九格无序精确匹配，50 tick搅拌；水奶每桶1000mB；空盛取物不占原料格 |
| 炒锅 | time=200、翻炒3次，数量展开；盛取物在完成后逐件消耗 |
| 汤锅 | time=300；水奶菜籽油汤底，菜籽油汤底ID为icecore:canola_oil；产量按整锅 |
| 茶壶 | 一份茶底与1000mB水奶，12杯；原生240 tick及倒茶流程，每杯需空茶杯 |
| 榨汁机 | 单原料真实果汁使用juice模式，混合饮料使用mixed模式；200 tick，重复原料展开为最多五个单件槽；水奶每桶1000mB，杯瓶逐件领取 |
| 榨油器 | 油饼1→1000mB菜籽油，原生16点压榨进度、6tick撞击间隔和10tick完成等待；不产油渣 |
| 烧烤架 | 原生翻面、火候、刷油和撒料；刷油仅菜籽油；调料按原生次数消耗，不作为盛取物 |
| 酒桶 | 4000mB基液、各固体16件→16瓶；每品质阶段2400 tick；无匹配不开始、不产醋 |
| 冰柜 | 1800 tick，最多4个单件原料，水奶每桶1000mB；木棍杯子为逐件盛取物 |
| 发酵桶 | 原生密封流程6000 tick，精确单件和流体匹配；结果按整批，碗瓶逐件领取 |
| 料理台 | 从真实原生base推导米饭海带阶段，保留ordered/mixed、完成与切分；蟹籽成品基底不重复扣蟹籽 |
| 木棍 | 原生grilling数据入口，材料顺序不改；一根木棍计入输入；生成生串与熟串关联 |

特制调料的管理器输出×16为单瓶可用16次，生成一个SeasoningUses=0物品，SeasoningIngredients保存九件真实原料。实际成品保留原生名称；空瓶名为空调料瓶。

榨汁机所有流体果汁每杯消耗250mB，桶仍为1000mB；每份原料的出汁量按管理器总杯数反推，不沿用上游500mB杯容量。葡萄每件产250mB，四件可装一桶或四杯。杯装和桶装使用独立管理配方并在JEI分别展示；桶装配方不注册extract，实际装桶复用上游FluidUtil，JEI补充空桶/果汁桶说明槽。

奶基混合配方使用榨汁机实际倒桶注入的`kaleidoscope_fragrantorchard:milk_still`，每桶1000mB；不把其它设备的`minecraft:milk`映射套用于榨汁机。证据为真实JuicerBlock奶桶分支及ModFluids注册。石榴沙司仍为两片石榴、鸡蛋、糖、冰块五格原料加一桶奶，按管理器产出一份，不提前消耗盛取杯。

## 重载与性能

物品显示按ID查表；容器共用有界缓存并随数据重载失效。混合碗领取前按配方对象和容器版本刷新要求；烤炉加工时按ID检查活动配方是否被替换；发酵桶重新进入原生搜索；榨汁机未完成批次停止并重新匹配，冰柜新批次保存已消耗输入快照以便失效退还。酒桶保存批次输入，完整失效批次退还；部分领取批次不退料，暂停酿造并保留最后有效盛取要求。各设备不得逐tick扫描管理器JSON。

料理台额外材料通过 `icecore:cuisine_model_alias/<原生变体>` 物品标签复用已注册的模型；当前生成carrot和mayonnaise映射，不创建替代料理台或模型阶段。
